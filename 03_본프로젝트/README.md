처음 받았다면 아래 순서로 읽는다. 문서·SQL·코드·그림을 한곳에서 훑어보는 화면도 있다(DB·인증키 불필요).

## 실행 방법 (11/25 갱신)

**대시보드만 볼 때**: 저장소 루트에서 `uv run streamlit run 03_본프로젝트/05_코드/app.py` → 브라우저 http://localhost:8501

```powershell
# 처음부터 다시 만들 때 (저장소 루트에서)
uv run python 03_본프로젝트/05_코드/fetch_reference.py     # 기준 정보·승하차 API 원본 내려받기 (1회)
#   2025 전체 승하차·역사심도 파일은 07_데이터/raw/file/에 있음 (공공데이터포털 15048032, 15071319)
uv run python 03_본프로젝트/05_코드/preprocess.py          # 원본 → 07_데이터/clean/*.csv (약 25초)
Get-Content -Raw -Encoding UTF8 03_본프로젝트/03_sql/01_schema.sql | mysql --login-path=endb   # DB 다시 만들기 (기존 데이터 삭제)
uv run python 03_본프로젝트/05_코드/load_db.py             # CSV → MySQL + 시간대 프로필 계산 (약 1분, 다시 실행해도 결과 동일)
mysql --login-path=endb subway_access_db < 03_본프로젝트/03_sql/04_views.sql    # 뷰 만들기
mysql --login-path=endb subway_access_db < 03_본프로젝트/03_sql/02_checks.sql   # 무결성 점검 (모두 0이면 정상)
mysql --login-path=endb subway_access_db < 03_본프로젝트/03_sql/03_queries.sql  # 질문 1·2·3 질의
mysql --login-path=endb --force subway_access_db < 03_본프로젝트/03_sql/05_constraint_tests.sql  # 제약조건 위반 테스트 (모두 ERROR여야 정상)
uv run python 03_본프로젝트/05_코드/analysis.py            # 역사 유형 군집 → CLUSTER_RUN·CLUSTER_RESULT, 04_결과/csv/*.csv
uv run python 03_본프로젝트/05_코드/visualize.py           # 그림 5개 → 04_결과/그림/*.png
uv run python 03_본프로젝트/05_코드/draw_erd.py            # DB 스키마 → 02_설계/ERD.png
uv run pytest 03_본프로젝트/06_테스트                      # 테스트 67건
```

- 수집: 작업 스케줄러 `ENDB_SubwayCollect`가 매시 `run_collect.cmd`를 실행한다. 수집(`collect.py`) 뒤 `preprocess.py --live` → `load_db.py --live`로 승강기·비가동·출입구 테이블을 DB에 바로 반영한다(약 2초, 로그 `07_데이터/snapshots/db_refresh.log`).
- 군집 분석은 승강기 수집이 3일(72시간) 이상 쌓이면 비가동 지표를 포함해 다시 실행한다. 중간 점검(12/2)과 수집 종료 후(12/8)에 `analysis.py` → `visualize.py`를 다시 돌린다.
