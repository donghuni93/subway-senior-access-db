# 후보 주제 계획 5개 (11/17) — 보류 (11/17 결정: 상권만 진행)

> 기준: (1) 기존 앱이 주지 않는 정보를 만든다 (2) 상태가 시간에 따라 바뀌고 이력이 쌓인다 (3) 사람에게 실제로 중요하다.
> 모든 항목의 "확인 수준"은 검색 결과 기준이다. 응답 필드와 이력 범위는 인증키로 호출해 보기 전까지 확정이 아니다.
> 현재 주제(고령 × 승강기)와 상권(연습 1), 콜택시(연습 2)는 제외한 새 후보다.

## 1. 응급실 포화 패턴

- **새 정보:** 앱은 "지금 병상이 있는가"만 준다. 우리는 "이 병원은 평일 밤 몇 시에 포화되는가", "이 지역은 언제 응급실 찾기가 어려운가"를 만든다.
- **사용자:** 만성 질환 보호자(병원 선택), 지자체 보건 담당(포화 시간대 파악), 구급대 운영 담당.
- **DB 근거:** 실시간 병상은 과거가 남지 않는다. 직접 쌓아야 이력이 생긴다. 상태 전이는 아니지만 시계열이다.
- **확인된 것:** 공공데이터포털에 2023.12~2024.11 시간대별 가용 병상·포화도 집계가 있다. 실시간 병상 API는 검색으로 명세를 확인하지 못했다.
- **위험:** 실시간 API가 없으면 직접 수집을 못 하고 과거 집계만으로 분석이 된다. 그러면 정적 분석에 가깝다.
- **첫 확인:** 공공데이터포털 인증키로 실시간 병상 API 호출, 응답 필드와 갱신 주기 확인.

## 2. 의약품 공급중단 이력

- **새 정보:** 현재 목록은 공개되지만, "어떤 성분이 자주 끊기는가", "중단에서 정상화까지 평균 며칠인가", "대체 의약품이 있는가"는 시간 축으로 쌓아야 보인다.
- **사용자:** 만성 질환자·약사, 병원 약제과, 보건 정책 담당.
- **DB 근거:** 중단 → 정상화는 승강기와 같은 상태 전이다. 보고일과 공개일의 차이(평균 128일 지연, 2023 국회 자료)도 분석 대상이다.
- **확인된 것:** 식약처가 2024.1부터 공급중단·부족 현황을 실시간 공개한다. 정상화 예상일, 정부 조치, 동일 성분 대체 목록이 제공 항목이다.
- **위험:** API 형태로 받을 수 있는지 불확실하다. 웹 페이지만 있으면 수집이 어렵다.
- **첫 확인:** 공공데이터포털에서 식약처·심평원 공급중단 데이터 검색, API 여부 확인.

## 3. 식품 회수·판매중지 반복 패턴

- **새 정보:** 알림 앱은 개별 회수를 알려 준다. 우리는 "같은 업체가 반복해서 회수되는가", "계절별 회수 사유 추이", "회수 이후 같은 사유 재발"을 만든다.
- **사용자:** 소비자, 학교·기관 급식 담당, 유통업체, 식품안전 담당 공무원.
- **DB 근거:** 회수 공표는 매일 추가되고 과거 이력이 누적된다. 업체·품목·사유로 정규화가 잘 된다.
- **확인된 것:** 행안부 '회수·판매중지정보' 데이터셋(이용 제한 없음), 경남 긴급회수 API(실시간 표기)가 있다. 식약처 알림은 2026.7.28부터 앱에서 실시간 제공된다.
- **위험:** 알림 자체는 이미 앱이 준다. 반복 패턴 분석이 차별점이므로, 반복 회수가 충분한지 데이터로 확인해야 한다.
- **첫 확인:** 행안부 데이터셋 필드, 건수, 이력 범위 확인.

## 4. 유기동물 보호 기간

- **새 정보:** 앱은 개체 정보와 입양 공고를 보여 준다. 우리는 "보호소별 입양·안락사·반환 비율", "품종·연령별 입양까지 걸린 일수", "공고 기한이 임박한 동물 목록"을 만든다.
- **사용자:** 입양 희망자, 지자체 동물보호 담당(과밀·고위험 보호소 파악), 자원봉사자.
- **DB 근거:** 공고 중 → 입양/반환/안락사/자연사의 상태 전이다. 지하철 승강기의 구조와 가장 닮았다.
- **확인된 것:** 농림축산식품부 구조동물 조회 API가 공공데이터포털에 있다. 시도·시군구·보호소·품종으로 조회한다.
- **위험:** 보호 결과(종료 상태) 필드와 과거 공고 이력이 응답에 있는지 모른다. 없으면 상태 전이를 만들 수 없다.
- **첫 확인:** 인증키로 호출해 종료 상태 필드와 이력 범위 확인.

## 5. 재난문자 발령 이력

- **새 정보:** 문자는 받는 순간만 알려 준다. 우리는 "우리 지역이 어떤 재난으로 얼마나 자주 경고받았는가", "기상 악화에서 문자까지의 시차", "연도별 증가 추이"를 만든다.
- **사용자:** 주민, 지자체 재난 담당, 보험·부동산 위험 평가.
- **DB 근거:** 발령은 매일 쌓이는 이력이고 기상 데이터와 시간으로 결합된다. 과거 소급이 가능할 가능성이 높다.
- **확인된 것:** 공공데이터포털 '재난문자방송발령현황' API를 연구가 사용한 사례가 있다. 2011~2022년 이력 분석 연구가 있다.
- **위험:** "문자가 많이 왔다"가 정보로서 약할 수 있다. 기상·인구와 결합하지 않으면 단순 통계에 그친다.
- **첫 확인:** API 필드(지역, 시각, 유형, 내용)와 이력 범위 확인.
