# 추가 데이터 후보 — 인구 (조사 메모, 2026-10-31)

> 상태 : **조사만 함. 제안서에는 넣지 않는다.**
> 제안서에는 "현재 지하철 데이터로 범위를 정리하고, 인구 등 지역 데이터는 추후 모델링 단계에서 결합을 검토한다" 수준으로 한 줄만 쓴다.
> 아래 데이터셋 ID·갱신 주기는 웹 검색 결과 기준이다. 실제로 쓰기 전에 열린데이터광장 페이지에서 내려받기 가능 여부와 최신 시점을 다시 확인한다.

## 1. 왜 고려하는가

- 고령 인구가 많은(또는 빠르게 늘어난) 지역의 역에서 고령 이용이 실제로 늘었는지 보여 줄 수 있다.
- 회귀·분류 모델의 설명 변수로 쓸 수 있다 (역 주변 65세 이상 비율, 생활인구 규모 등).
- 역코드 ↔ 행정동 연결 테이블이 생기므로 ER 설계·정규화 사례가 하나 늘어난다.

## 3. 역 ↔ 행정동 연결 방법

공통 키가 다르다 (지하철 = 역코드, 인구 = 행정동 코드). 방법은 쉬운 순서로 세 가지다.

1. **OA-21224 행정동별 지하철 승차를 다리로 쓰기 (가장 쉬움)**
   - 이미 `05_1031_데이터탐색_지하철175건.md`에 있는 데이터다. 일자 × 행정동 × 24시간 승차 인원.
   - 역 단위 대신 **행정동 단위로 분석**하면 인구 데이터와 행정동 코드로 바로 붙는다. 좌표 작업이 필요 없다.
   - 단점 : 역별 승강기·출입구 정보와는 다시 행정동으로 묶어야 한다.
2. **OA-22493 자치구별 지하철역 → 자치구 단위 결합**
   - 역 → 자치구 매핑만 있으면 된다. 단, 자치구(25개)는 너무 굵어서 모델 변수로는 약하다.
3. **역 좌표 + 행정동 경계로 공간 결합 (가장 정확, 손이 많이 감)**
   - 역 좌표 : OA-21232 역사마스터(위경도, 로그인·권한 신청 필요해 보임), OA-22534 역사 좌표
   - 행정동 경계 : GitHub `raqoon886/Local_HangJeongDong`(행정동 GeoJSON, `adm_nm`), 국가공간정보포털 원본 SHP(UTM-K → WGS84 변환 필요)
   - 주의 : 법정동 경계(행안부 "읍면동법정경계")와 혼동하지 않는다. 오래된 경계 파일은 최근 행정동 개편이 빠져 있을 수 있다.
   - Python `geopandas`의 point-in-polygon으로 역마다 행정동을 붙여 `역_행정동` 테이블로 저장.

## 4. 나중에 정할 것

- 분석 단위를 역으로 할지 행정동으로 할지 (위 1번을 쓰면 행정동)
- 인구 기준 시점을 승하차 데이터 기간(2021-07~)과 어떻게 맞출지 (분기 인구 → 월·일 데이터에 붙이는 규칙)
- 주민등록 인구(거주)와 생활인구(체류) 중 무엇이 문제에 맞는지
