## 과제 개요

엔지니어링DB 텀프로젝트. 공공데이터로 DB를 설계(교재 8·9장 절차 : 요구사항분석 → ER 모델링 → 정규화 검증)하고, SQL 질의 → 분석 모델링 → 시각화로 특정 도메인에 필요한 정보를 만들어 내는 정보시스템을 구현한다. 2인 1조, 임베디드 SQL 필수, MySQL Workbench 권장.

## 지금까지 정한 것

1. **주제** : 지하철 무임승차. 10년치 유·무임 승하차 + 인구 통계 + 혼잡도 (+ 역별 시설물)를 연결해, 무임승차 문제 해결에 도움이 되는 정보를 제공하는 시스템.
2. **시스템 성격** : 데이터 분석 프로젝트가 아니라 **정보제공 시스템**. 최소 15일 이상 데이터를 주기적으로 삽입·삭제하며 운영하고, 사용자가 조건을 넣으면 항상 맞는 정보를 돌려받는 구조.
3. **검토 중인 가설** : "접근성 시설(엘리베이터·에스컬레이터 등)이 잘 갖춰진 역일수록 무임 승객 **비율**이 높다."
   - 절대 인원이 아니라 비율로 볼 것 (역 규모 효과 제거)
   - 통제 변수 : 자치구 고령 인구 비율, 환승역 여부
   - 시설물 데이터에 설치연도가 있으면 설치 전후 비교로 강화
4. **데이터 선정 원칙** : 시스템이 답할 질문을 먼저 정하고, 그 질문에 쓰이면서 다른 테이블과 키(역번호·자치구·연월)로 연결되는 데이터만 넣는다. 관련 CSV를 무작정 넣지 않는다.
5. **초안 테이블 구조** : `역`, `시설물`(역 1 : N), `일별_승하차`, `월별_승하차`(요약), `자치구_인구`, `혼잡도`(세로형으로 변환), `load_log`(적재 이력)
6. **작업 방식**
   - Opus 5.5 : 요구사항, ER·정규화 설계, 보고서
   - Sonnet 5.5 : 코드 (Jupyter 셀, 적재 스크립트, 질의). 단순 셀은 Haiku 5.5
   - `schema.sql`과 SQL 질의문은 Claude가 쓰더라도 **사용자가 한 줄씩 직접 읽고 이해**한다 (발표·보고서에서 설명해야 하므로)
   - 테이블명·열이 코드 전체에서 맞물리도록, 코드 요청 시 `요구사항.md`와 `schema.sql`을 함께 준다

## 아직 확인 안 된 것 (리스크)

- [ ] **매일 갱신되는 데이터가 있는가** : 15일 운영의 전제. 서울 열린데이터광장 역별 일별 승하차가 매일 갱신되는 것으로 알지만 미확인. 갱신 지연(며칠 늦게 올라오는지), API 키 승인 필요 여부도 확인.
- [ ] **유·무임 구분이 일별로 나오는가** : 월 단위로만 나오면 "일별 총 승하차 + 월별 유·무임"으로 설계를 나눈다.
- [ ] **혼잡도 데이터 구조** : 사용자가 로컬 `data/`에 올려둠. claude.ai 채팅에서는 못 봤으므로 Cowork에서 처음 열어볼 것. 시간대가 열로 펼쳐진 가로형이면 세로형으로 바꾸는 것이 정규화(1NF) 사례가 된다.
- [ ] **시설물 데이터에 설치연도 열이 있는가** : 있으면 전후 비교, 없으면 역간 비교.
- [ ] **역 연결 키** : 기관마다 역명 표기("서울역" vs "서울")와 역번호 체계가 다를 수 있음. 매핑표 필요 여부 확인.
- [ ] MySQL 설치 여부 (어려우면 SQLite로 먼저 연습)
