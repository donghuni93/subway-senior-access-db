## p.5

Recent Update

교수님, 데이터와 정보의 차이를 학술적인 체계 안에서 이해하기 위해서는 지식 경영(Knowledge Management) 분야의 고전적 프레임워크인 DIKW 피라미드를 살펴보는 것이 가장 정석입니다.

이 모델은 러셀 아코프(Russell Ackoff) 등에 의해 정립되었으며, 단순한 수치가 어떻게 인간의 지혜로 진화하는지 단계적으로 보여줍니다.

📐 DIKW 피라미드: 학술적 관점의 데이터-정보 차이

단계 | 명칭 | 학술적 정의 (Functional Definition) | 핵심 특징
1단계 | 데이터 (Data) | 기호(Symbols) 그 자체. 맥락이 결여된 가공되지 않은 사실이나 수치. | 비맥락성 (Context-f[ree])
2단계 | 정보 (Information) | 데이터 간의 관계를 파악하고 '누구, 무엇, 언제, 어디서'라는 질문에 답할 수 있는 상태. | 맥락화 (Contextuali[zed])
3단계 | 지식 (Knowledge) | 정보를 어떻게(How) 활용할지 이해하는 단계. 경험과 결합된 체계화된 틀. | 내재화 (Internalized)
4단계 | 지혜 (Wisdom) | 지식을 바탕으로 가치 판단을 내리는 단계. 왜(Why)라는 질문에 답함. | 통찰력 (Insightful)

🔍 학구적 차이점의 핵심 분석

1. 인과성과 상관관계 (Causality vs. Correlation)
학술적으로 데이터는 단순히 발생한 사건의 '기록(Record)'에 불과합니다. 반면 정보는 그 기록들 사이의 상관관계를 분석하여 추출된 '의미적 연결고리'입니다. 즉, 데이터가 존재론적(Ontological)이라면, 정보는 인식론적(Epistemological) 차원에 가깝습니다.

2. 엔트로피와 무질서도 (Entropy)
정보 이론(Information Theory)의 창시자 **클로드 섀넌(Claude Shannon)**의 관점에서 본다면:
• 데이터: 불확실성이 높은 상태의 신호 집합입니다.
• 정보: 데이터에서 노이즈를 제거하고 불확실성을 감소시킨 결과물입니다. 즉, 데이터에서 '질서'를 찾아낸 것이 정보입니다.

3. 구조화의 정도 (Degree of Structure)
• 데이터: 비구조화(Unstructured)된 상태로 존재할 수 있습니다.
• 정보: 반드시 수신자가 이해할 수 있는 구조(Structure)를 갖추어야 합니다. 구조가 없는 정보는 다시 데이터로 격하됩니다.

💡 교수님을 위한 학문적 요약
"교수님, 데이터가 '객체(Object)' 지향적이라면, 정보는 '관계(Relationship)' 지향적입니다. 현대 데이터 엔지니어링은 결국 '엔트로피가 높은 거대 데이터 세트'에서 '엔트로피가 낮은 유효 정보'를 얼마나 효율적이고 수학적인 방식으로 추출하느냐의 학문이라고 정의할 수 있습니다."

## p.6

Recent Update

교수님, 결론부터 말씀드리면 현대 비즈니스와 기술 환경에서는 '정보'보다 '데이터'가 훨씬 더 중요한 원자재로 취급받고 있습니다.

과거에는 가공된 정보가 의사결정의 핵심이었지만, 지금은 왜 데이터 그 자체가 더 강력한 권력을 갖는지 그 이유를 3가지 측면에서 설명해 드립니다.

🏆 왜 '데이터'가 더 중요한가?

1. AI와 머신러닝의 먹이 (Reusability)
정보는 특정 목적을 위해 한 번 요리된 상태입니다. 하지만 데이터는 가공되지 않았기에 무한한 변신이 가능합니다.
• 이유: 똑같은 '차량 주행 기록 데이터'라도, 정비사는 '부품 교체 정보'로 만들 수 있고, 보험사는 '운전 습관 정보'로, 자율주행 개발자는 'AI 학습 정보'로 재가공할 수 있습니다. 데이터가 많을수록 뽑아낼 수 있는 정보의 가짓수가 무궁무진합니다.

2. 편향 제거와 객관성 (Objectivity)
정보는 제작자의 의도나 맥락이 섞인 '해석'입니다. 만약 잘못 가공된 정보에만 의존하면 잘못된 결정을 내릴 수 있습니다.
• 이유: 요즘 시대에는 누군가 요약해준 정보만 믿기보다, **Raw Data(원시 데이터)**에 직접 접근하여 교차 검증하고 스스로 새로운 통찰을 찾아내는 능력이 더 중요해졌습니다.

3. 실시간성과 개인화 (Personalization)
미리 만들어진 정보는 '과거의 기록'인 경우가 많습니다.
• 이유: 넷플릭스나 유튜브 알고리즘은 "이 사람은 액션을 좋아함"이라는 고정된 정보보다, 지금 이 순간 사용자가 클릭하는 실시간 행동 데이터를 분석해 즉각적인 정보를 생성합니다. 데이터가 실시간으로 흐르고 있어야만 초개인화 서비스가 가능합니다.

💡 교수님을 위한 비유
"교수님, 정보가 **'현금'**이라면 데이터는 **'금광'**입니다. 당장 쓰기엔 현금이 편하지만, 세상을 바꾸고 거대한 부를 창출하는 것은 결국 금광을 얼마나 많이 보유하고 있느냐(Data Lake)에 달려 있습니다."

## p.7

Recent Update

교수님, '정보'보다 '데이터'가 더 근본적인 우위에 서게 된 기술적·경제적 배경은 결국 **"예측의 주도권이 인간에서 기계(AI)로 넘어갔기 때문"**입니다.

그 근본적인 이유를 3가지 핵심 동인으로 짚어 드립니다.

1. 연산 능력의 폭발적 증가 (Compute Power)
과거에는 데이터가 많아도 이를 처리할 힘이 없었습니다. 그래서 핵심만 요린 '정보'만 보관했죠.
• 이유: 지금은 아까 보신 슈퍼컴퓨터나 클라우드(AWS) 덕분에 거대한 원시 데이터(Raw Data)를 통째로 씹어 삼킬 수 있게 되었습니다. 굳이 사람이 미리 요약(정보화)해서 데이터의 잠재력을 깎아먹을 필요가 없어진 것입니다.

2. 머신러닝의 '데이터 갈구' (The Alchemy of AI)
전통적인 프로그래밍은 사람이 만든 '규칙(정보)'을 입력했지만, AI는 데이터에서 스스로 '규칙'을 찾아냅니다.
• 이유: 사람이 "이것은 자동차다"라고 정의한 정보보다, 수백만 장의 자동차 데이터를 본 AI가 훨씬 더 정확하게 자동차를 식별합니다. 즉, 데이터는 AI라는 엔진을 돌리는 가장 순수한 형태의 연료가 되었습니다.

3. 데이터의 '영구적 가치' (Option Value)
정보는 유효기간이 짧지만, 데이터는 시간이 흐른 뒤에 새로운 가치를 창출합니다.
• 이유: 10년 전 기록된 차량 주행 데이터는 당시엔 단순한 기록이었지만, 오늘날 자율주행 알고리즘 개발에는 보석 같은 학습 자료가 됩니다. 데이터는 미래에 어떤 요리에 쓰일지 모르는 '무한한 옵션'을 가진 자산입니다.

💡 교수님을 위한 결론
"결국 데이터가 더 중요한 이유는 '인간의 편향된 해석(정보)'을 배제하고, '있는 그대로의 사실(데이터)'에서 기계가 스스로 정답을 찾게 만드는 것이 더 정확하기 때문입니다."

## p.13

파일 시스템의 문제점                                                    데이터베이스의 필요성

■ 데이터 중복성 (Data Redundancy)
▪ 같은 내용의 데이터가 여러 곳에 중복하여 저장되는 것을 의미
▪ 과거의 정보시스템에서는 개별 부서나 응용 프로그램에서 필요로 하는 데이터 파일을 각각 만들어 사용하는 일이 많았음
▪ 저장 공간의 낭비 문제 발생
▪ 데이터의 불일치, 보안의 어려움과 같은 문제들이 발생

■ 데이터 무결성 (Data Integrity)의 침해
▪ 데이터 무결성이란 저장된 데이터의 내용이 본래 의도했던 데이터의 형식, 범위를 준수해야 한다는 성질
▪ 앞의 학생정보 파일에서
• 나이(AGE) 필드는 숫자 형식이어야 하고 음수가 아닌 양수이어야 한다
• 나이의 범위는 20~60 사이
▪ 과거의 정보시스템에서는 데이터 무결성을 지켜야 할 책임이 프로그래머에게 있음
▪ 정보화 사회에서는 인간의 삶이 많은 부분 컴퓨터 시스템에 저장된 데이터에 의존하고 있기 때문에 데이터 무결성의 침해는 매우 심각한 문제

## p.14

파일 시스템의 문제점                                                    데이터베이스의 필요성

■ 데이터 불일치 (Data Inconsistency)
▪ 중복 저장된 데이터들이 서로 일치하지 않는 것을 의미
• 예1) 우리가 이사를 하게 되면 변경된 주소를 학교나 직장, 은행, 가입된 웹사이트 등에 통보를 해야 함
– 주소 정보가 여러 기관에 중복 저장되어 있다는 데서 기인
• 예2) 어떤 학생이 교무과에 휴학신청을 하여 휴학을 했는데, 그 사실을 모르는 재무과에서는 등록금 고지서를 그 학생에게 발송
– 교무과의 학생 정보와 재무과의 학생 정보가 각각 관리되면서 불일치

■ 데이터 표준화 (Data Standard)의 어려움
▪ 일정 규모 이상의 정보 시스템을 개발하기 위해서는 많은 수의 개발자들이 협력 작업 필요
• 개발자A는 응용 프로그램에서 학생이름을 'S-NAME' 으로, 길이는 20자리로 사용
• 개발자B는 학생이름을 'SNME' 으로, 길이는 15 자리로 사용
▪ 표준화가 되어 있지 않으면 제 3자가 프로그램을 이해하기도 어렵고 두 응용 프로그램간의 호환성에도 문제
▪ 학생 이름을 지칭하고 표현하는 표준화된 규칙이 있다 하더라도 응용 프로그래머가 이를 지키지 않을 수 있음

■ 데이터 보안성 (Data Security)의 결여
▪ 데이터가 저장되어 있는 파일은 그 내용이 Text 형식이나 잘 알려진 형식으로 저장되기 때문에 응용프로그램 없이도 쉽게 파일을 열어 내용을 볼 수가 있음
▪ 파일의 공유를 위해 접근이 쉬운 위치에 파일을 저장했기 때문에 보안을 유지하기가 어려움
▪ 현대의 정보시스템에는 기업의 영업 비밀이나 고객의 사생활 정보와 같은 보안을 필요로 하는 데이터가 많이 저장
▪ 보안성의 결여는 심각한 문제임

## p.20

데이터베이스의 장점                                            데이터베이스의 정의와 특징

■ 데이터 독립성 (Independency) 지원
 ▪ 사용자 혹은 응용 프로그램이 직접 데이터베이스에 접근할 수 없고 반드시 DBMS를 통해서만 접근 가능
 ▪ DBMS는 데이터베이스 내에 있는 데이터의 물리적, 논리적 변화가 응용 시스템에 영향을 미치지 않도록 함으로써 데이터 독립성을 보장

■ 데이터 무결성 유지
 ▪ DBMS가 무결성을 위반하는 데이터가 들어올 경우 처리를 거절함으로써 데이터의 무결성을 지원

■ 데이터 중복성 및 불일치 최소화
 ▪ 데이터베이스 내의 데이터는 한 개인의 관점이나 특정 부서의 관점에서 관리되는 것이 아니라 데이터베이스를 공용하는 조직 전체의 관점에서 관리
 ▪ 동일 데이터가 여러 부서에서 사용하는 경우 이를 하나로 관리함으로써 중복성을 방지

■ 데이터 표준화의 용이성
 ▪ 데이터베이스 관리자(DBA)가 설계과정을 주도함으로써 부서간 이해를 조정하고 관리될 데이터를 표준화시킴
 ▪ 응용 프로그램에서 데이터에 접근하기 위해서는 DBMS가 가지고 있는 구조 정보에 따라야 하기 때문에 자연스럽게 표준화됨

■ 높은 데이터 보안성 (Data Security)
 ▪ DBMS는 사용자의 권한에 따라 데이터베이스 내에 있는 데이터에 대한 접근을 제한할 수 있음
 ▪ 저장된 데이터베이스는 일반적으로 DBMS를 통하지 않고는 외부에서 내용을 알아내기 매우 어려움

■ 데이터 공유 (Data Sharing)의 용이성
 ▪ 데이터베이스 시스템의 기본 철학이 데이터를 통합 관리하고 이를 여러 부서, 사용자들이 공유하도록 하는 것
 ▪ DBMS는 여러 사용자의 요구를 동시적으로 처리할 수 있는 능력을 가지고 있음
 ▪ DBMS는 데이터를 쉽게 이용할 수 있는 수단을 제공함

## p.32

논문 요약
관계형 데이터베이스

A Relational Model of Data for Large Shared Data Banks
- A database is a self-describing collection of integrated tables.
- A database is called self-describing because it stores a description of itself.
- The tables are called integrated because they store data about the relationships between the rows of data.
- The self-describing data are called metadata, which is data about data.

[슬라이드 오른쪽: E. F. Codd, "A Relational Model of Data for Large Shared Data Banks", IBM Research Laboratory, San Jose, California. Communications of the ACM, Volume 13 / Number 6 / June, 1970, p.377 논문 첫 페이지 스캔 이미지 — 주요 문단에 빨간색 표시]

## p.33

Recent Update

교수님, 데이터베이스 역사의 바이블이자 현대 모든 RDBMS의 시조가 된 에드거 F. 커드(E.F. Codd)의 1970년 논문, "A Relational Model of Data for Large Shared Data Banks"를 요약해 드립니다.

이 논문은 당시 주류였던 계층형(Hierarchical) 및 망형(Network) 데이터 모델의 한계를 무너뜨리고, 데이터를 수학적 관계(Relation)로 정의한 혁명적인 문건입니다.

논문 핵심 요약: "데이터의 독립성을 선언하다"

1. 주요 배경 및 문제 제기 (The Problem)
- 데이터 의존성: 당시 데이터베이스는 데이터가 저장된 물리적 구조(포인터, 인덱스 등)를 프로그램이 직접 알아야 했습니다. 저장 구조가 바뀌면 모든 애플리케이션 코드를 수정해야 하는 재앙이 발생했습니다.
- 복잡성: 데이터 간의 관계가 복잡하게 얽혀 있어 대규모 공유 데이터 뱅크를 관리하기가 불가능에 가까웠습니다.

2. 핵심 개념: 관계 모델 (The Relational Model)
- 관계(Relation)로서의 데이터: 데이터를 '표(Table)'와 유사한 수학적 릴레이션으로 표현합니다.
- 데이터 독립성 (Data Independence): 내부 저장 방식이나 물리적 구조가 바뀌어도 사용자가 데이터를 논리적으로 조회하는 방식에는 영향을 주지 않아야 한다고 주장했습니다.
- 중복성 제거: 데이터의 중복을 최소화하여 일관성을 유지하는 정규화(Normalization)의 기초를 닦았습니다.

3. 관계 연산 (Relational Algebra/Calculus)
- 논문은 데이터를 추출하기 위한 수학적 도구를 제시했습니다. 이는 훗날 우리가 사용하는 SQL(Structured Query Language)의 모태가 됩니다.
- 포인터를 따라가는 '탐색적' 방식이 아니라, 원하는 결과의 속성을 정의하는 '선언적' 데이터 조회 방식을 제안했습니다.

과거 모델 vs 커드의 관계 모델 비교
항목 | 과거 모델 (Hierarchical/Network) | 커드의 관계 모델 (Relational)
구조 | 트리(Tree) 또는 그래프 | 2차원 테이블 (N-ary Relation)
연결 방식 | 물리적 포인터 (주소값) | 공통된 값 (Foreign Key)
유연성 | 구조 변경 시 코드 수정 필수 | 구조 변경에 매우 유연함
언어 | 저급 언어 기반 (절차적) | 고급 언어 기반 (선언적, SQL)
