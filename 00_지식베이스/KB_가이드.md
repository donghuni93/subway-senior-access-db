# 엔지니어링DB 지식 베이스 가이드

강의노트(아주대 엔지니어링DB 2026)를 DB 엔지니어링 질의의 기준 자료로 쓰기 위한 지식 베이스다.

## 구조
- `raw/` 원본. 수정하지 않는다. `raw/md/`가 검색 대상, `raw/lab/`은 Lab1·Lab2 실습 파일(MySQL 동작 근거), 나머지는 보관용.
- `wiki/index.md` 장·개념 색인. 질의는 여기서 시작한다.
- `wiki/chNN_*.md` 장별 요약.
- `wiki/concepts/*.md` 개념 카드 (파일명은 한글 개념명, 예: `제3정규형.md`).
- `wiki/sql_patterns/` SQL 패턴과 과제에서 겪은 오류 사례.
- `wiki/glossary.md` 한글↔영문 용어 대응.

## 질의 규칙 (DB 질문에 답할 때)
1. `wiki/index.md`에서 관련 카드를 찾고, 필요하면 `raw/md/`의 해당 쪽(`## p.N`)을 확인한다.
2. 강의 내용으로 답하고 출처를 `(04장 p.12)` 형식으로 붙인다.
3. 강의에 없는 내용은 `[강의 범위 밖: 모델 일반 지식]`으로 표시해 구분한다.
4. 강의와 일반 지식의 표기·정의가 다르면 차이를 밝히고, 과제·시험에서는 강의 표기를 따른다.
5. 카드 내용이 의심되면 raw 원문을 우선한다.

## 장별 요약 형식 (`wiki/chNN_제목.md`)
```
# NN장 제목
## 학습 목표        (강의 학습 목표 그대로)
## 핵심 요약        (불릿 10개 안팎, 각 항목 끝에 (p.N))
## 개념 목록        ([[개념명]] 링크)
## 시험·과제 포인트  (강의가 강조하거나 예제로 다룬 것)
```

## 개념 카드 형식 (`wiki/concepts/개념명.md`)
```
---
name: 개념명
english: English term
chapter: NN장
pages: p.a-b
related: [다른 개념, ...]
---
## 정의          (강의 표현 그대로, 1~3문장)
## 핵심 내용      (구분·종류·조건·기호 표기)
## 예시          (강의 예제의 값을 그대로. 표는 마크다운 표)
## 흔한 실수/혼동
## 출처          (NN장 p.N)
```
규칙: 강의 원문에 없는 내용을 사실처럼 쓰지 않는다. 보충이 필요하면 `[강의 범위 밖]` 표시를 붙인다. 개념 하나당 카드 하나, 길이는 40줄 이내.
