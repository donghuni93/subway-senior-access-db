# 03장 데이터베이스 시스템

## 학습 목표
- 데이터베이스, 데이터베이스 관리 시스템, 데이터베이스 시스템의 차이를 이해한다. (p.2)
- 데이터베이스 3단계 구조에서 데이터 독립성의 개념을 실현하는 방법을 이해한다. (p.2)
- 데이터베이스 사용자별 특징을 알아본다. (p.2)

## 핵심 요약
- 데이터베이스 시스템(DBS)은 데이터베이스에 데이터를 저장·관리하여 조직에 필요한 정보를 생성해주는 시스템이다. (p.4)
- 스키마는 데이터 구조와 제약조건의 정의, 인스턴스는 스키마에 따라 실제 저장된 값(레코드)이다. (p.6)
- 3단계 구조(ANSI/SPARC)는 외부(개별 사용자)·개념(조직 전체)·내부(저장 장치) 단계로 나뉜다. (p.7)
- 외부 스키마는 여러 개(서브 스키마), 개념 스키마와 내부 스키마는 각각 하나이다. (p.8-10)
- 개념 스키마에는 데이터·관계·제약조건뿐 아니라 보안 정책과 접근 권한 정의도 포함된다. (p.9)
- 내부 스키마는 레코드 구조, 필드 크기, 접근 경로 등 물리적 저장 구조를 정의한다. (p.10)
- 사상: 외부/개념 사상은 응용 인터페이스, 개념/내부 사상은 저장 인터페이스이다. 3단계 구조의 궁극적 목적은 데이터 독립성 실현이다. (p.12)
- 논리적 독립성은 개념 스키마 변경이 외부 스키마에 영향 없는 것, 물리적 독립성은 내부 스키마 변경이 개념 스키마에 영향 없는 것이다. (p.13)
- 데이터 사전(시스템 카탈로그)은 메타데이터를 유지하며 검색만 가능하고, 데이터 디렉터리는 위치 정보를 저장하며 일반 사용자 접근 불가이다. (p.15)
- 데이터 언어는 DDL(스키마 정의·수정·삭제), DML(삽입·삭제·수정·검색), DCL(규칙·기법 정의)로 구분한다. (p.17-18)
- DML은 절차적(What+How)과 비절차적(What만, 선언적)으로 나뉘고, DCL은 무결성·보안·회복·동시성 제어를 목적으로 한다. (p.18)
- 사용자는 DBA(DDL·DCL), 최종 사용자(DML, 캐주얼·초보), 응용 프로그래머(DML 삽입)로 구분한다. (p.19-21)
