# 05장 관계 데이터 모델
## 학습 목표
- 관계 데이터 모델의 기본 용어를 익힌다.
- 릴레이션을 구성하는 요소와 특성을 이해한다.
- 릴레이션에서 키의 역할과 종류를 알아본다.
- 무결성 제약의 의미와 필요성을 이해한다. (p.2)

## 핵심 요약
- 데이터 모델 = 데이터 구조 + 연산 + 제약조건. (p.4)
- 관계 데이터 모델은 1970년 E.F. Codd가 만들었고, 개념적 구조를 논리적 구조로 표현하며 하나의 개체를 하나의 릴레이션(테이블)에 저장한다. 상용 DBMS의 표준 모델. (p.5)
- 릴레이션=파일, 속성(열)=필드, 투플(행)=레코드. (p.6)
- 도메인은 속성이 가질 수 있는 값의 집합, 널은 모르거나 해당 없는 값, 차수는 속성 수, 카디널리티는 투플 수. 예: 고객 릴레이션 차수 6, 카디널리티 4. (p.7-8)
- 릴레이션은 스키마(내포, 정적)와 인스턴스(외연, 동적)로 구성되고, DB도 스키마와 인스턴스로 구성된다. (p.13-14)
- 릴레이션의 특성: 투플의 유일성, 투플·속성의 무순서, 속성의 원자성. 다중 값 셀은 부적합. (p.15)
- 함수 종속은 한 속성(들)이 다른 속성(들)을 결정하는 관계이며 왼쪽이 결정자. 방정식이 아니다. (p.16-19)
- 키는 투플을 유일하게 구별하는 속성(들)이며 유일성과 최소성을 가진다. (p.20)
- 키의 종류: 슈퍼키(유일성) ⊃ 후보키(유일성+최소성) ⊃ 기본키/대체키. 대리키는 인위적으로 추가한 기본키 열. (p.21-24, p.30)
- 외래키는 다른 릴레이션의 기본키를 참조하며 이름은 달라도 도메인은 같아야 한다. 여러 개 가능, 자기 참조 가능, 널 가능. (p.25-29)
- 무결성 제약조건: 개체 무결성(기본키는 널 불가)과 참조 무결성(외래키는 참조할 수 없는 값 불가). (p.32-34)
- 외래키가 널이어도 참조 무결성 위반이 아니다. (p.36)

## 시험·과제 포인트
- 고객 릴레이션 예: 차수·카디널리티 세기, 슈퍼키/후보키/기본키/대체키 구분((고객이름, 주소)는 후보키이자 대체키). (p.8, p.21-22)
- 위반 예: 기본키가 NULL(그림 5-14), 존재하지 않는 외래키 값 cherry(그림 5-15), 외래키 NULL은 위반 아님(그림 5-16). (p.33-36)
- 다중 값 직업('회사원, 학생')은 릴레이션으로 부적합. (p.15)
- 함수 종속 예: (OrderNumber, SKU) -> (Quantity, Price, ExtendedPrice), (Quantity, Price) -> ExtendedPrice, Buyer -> Department. (p.17-18)
- 외래키 사례: 학생·상담·교사 스키마(외래키 여러 개), 고객의 추천고객(자기 참조). (p.28-29)
