# 09장 정규화
## 학습 목표
- 정규화의 필요성과 이상 현상의 의미를 이해한다.
- 정규화를 수행하기 위해 함수 종속의 개념을 이해한다.
- 정규형의 유형과 관계를 이해하고, 실제 예를 통해 정규화 과정을 연습해본다.
- 트랜잭션 개념을 이해한다(10장). (p.2)

## 핵심 요약
- 정규화는 이상 현상을 제거하며 데이터베이스를 올바르게 설계해 나가는 과정이다. 이상 현상은 불필요한 데이터 중복 때문에 삽입·수정·삭제 시 생기는 부작용이다. (p.4)
- 이상 현상은 삽입 이상, 갱신 이상, 삭제 이상 세 가지이며, 이벤트참여(고객아이디, 이벤트번호, 당첨여부, 고객이름, 등급) 릴레이션의 melon 삽입, apple 등급 변경, orange 삭제 사례로 설명한다. (p.5-8)
- 함수 종속 X → Y: X는 결정자, Y는 종속자. 속성의 의미로 판단하고 현재 값만으로 판단하지 않는다. (p.10-11)
- 완전 함수 종속은 X 전체에 종속, 부분 함수 종속은 X의 일부에도 종속. 당첨여부는 완전, 고객이름은 부분 종속. (p.12, p.16)
- 정규화는 무손실 분해여야 하며 분해된 릴레이션을 자연 조인하면 원래 릴레이션이 복원되어야 한다. (p.18)
- 정규형: 1NF, 2NF, 3NF, BCNF(기본), 4NF, 5NF(고급). 차수가 높을수록 제약이 엄격하며 포함 관계 비정규형 ⊃ 1NF ⊃ 2NF ⊃ 3NF ⊃ BCNF ⊃ 4NF ⊃ 5NF. (p.19-20)
- 1NF: 모든 속성의 도메인이 원자 값. 1NF여도 등급·할인율의 부분 함수 종속 때문에 이상이 남는다. (p.21-27)
- 2NF: 1NF + 기본키가 아닌 모든 속성이 기본키에 완전 함수 종속. 분해로 고객, 이벤트참여를 얻는다. (p.28-32)
- 3NF: 2NF + 이행적 함수 종속 없음. 고객을 고객, 고객등급으로 분해하여 최종 3개 릴레이션을 얻는다. (p.33-39)
- BCNF: 모든 결정자가 후보키. 강좌신청을 고객담당강사, 강좌담당으로 분해한다. (p.40-45)
- 4NF는 BCNF + 다치 종속(A ↠ B) 제거(STUDENT → STU-MAJOR, STU-ACT), 5NF는 4NF + 후보키를 통하지 않는 조인 종속 제거. 실무에서는 3NF나 BCNF까지가 많고 4NF는 다치 종속 발생 시에만 수행한다. (p.46-48)
- 별첨1: 엔티티 타입 통합·분리의 성능 영향, 식별자·비식별자 관계 선택. 별첨2: MongoDB 개요. (p.52-67)

## 시험·과제 포인트
- 이벤트참여 예제 전 과정: 1NF(다중 값 분리) → 2NF(고객, 이벤트참여) → 3NF(고객, 고객등급) 결과 표와 FD 쓰기. (p.22-39)
- 각 정규형의 정의 문장과 "무엇을 제거하는가"(부분 종속, 이행적 종속, 후보키가 아닌 결정자). (p.48)
- BCNF 예제: 후보키 {고객아이디, 인터넷강좌}, {고객아이디, 담당강사번호}와 담당강사번호 → 인터넷강좌. (p.41-45)
- 4NF 예제 STUDENT(SID, Major, Activity)의 SID ↠ Major, SID ↠ Activity. (p.46-47)
- 이상 현상 표에서 삽입·갱신·삭제 이상을 각각 지목하기. (p.6-8, p.26, p.33, p.43)
- 원문 [판독 불확실]: p.58 EQUIPMENT 박스 제목, p.61 REP 속성 목록, p.66 MongoDB JSON.
