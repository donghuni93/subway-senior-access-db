# 08장 데이터베이스 설계
## 학습 목표
- 데이터베이스 설계의 중요성과 목표를 이해한다.
- 데이터베이스 설계 5단계를 학습한다.
- 요구 사항 분석, 개념적/논리적 설계의 과정을 실제 예를 통해 연습 해본다. (p.2)

## 핵심 요약
- 데이터베이스 설계는 사용자의 요구 사항을 고려해 데이터베이스를 생성하는 과정이며, 대표 방법은 E-R 모델과 릴레이션 변환 규칙을 이용한 설계와 정규화를 이용한 설계(9장)이다. (p.4)
- 설계는 요구 사항 분석 → 개념적 설계 → 논리적 설계 → 물리적 설계 → 구현의 5단계이고, 오류 발견 시 이전 단계로 되돌아갈 수 있다. 개념적~논리적 설계가 핵심 단계이다. (p.4-5)
- 단계별 결과물: 요구 사항 명세서 / 개념적 스키마(E-R 다이어그램) / 논리적 스키마(릴레이션 스키마) / 물리적 스키마. (p.5)
- 요구 사항 분석은 주요 사용자 범위 결정, 업무 분석, 면담·설문·문서 분석으로 요구 사항 수집, 명세서 작성으로 이루어진다. (p.7)
- 개념적 설계는 개체·속성 추출(명사) → 관계 추출(동사, 매핑 카디널리티·참여 특성) → E-R 다이어그램 작성의 3 STEP이다. (p.13-14, p.22)
- 한빛 마트 예제에서 개체 4개(회원, 상품, 제조업체, 게시글)와 관계 3개(주문 n:m, 공급 1:n, 작성 1:n)를 추출했다. (p.19, p.28)
- 논리적 설계는 E-R 다이어그램을 릴레이션 스키마로 변환하고 데이터 타입·길이·널 허용·기본값·제약조건을 정해 문서화한다. (p.35)
- 변환 규칙: 1 개체→릴레이션, 2 n:m→릴레이션, 3 1:n→외래키(3-2는 약한 개체), 4 1:1→외래키(4-1/4-2/4-3), 5 다중 값 속성→릴레이션. 순서대로 적용하되 해당 없는 규칙은 제외. (p.36)
- 한빛 마트 변환 결과는 회원, 상품, 제조업체, 게시글, 주문의 5개 릴레이션이며 규칙 4·5는 적용되지 않았다. (p.61-62)
- 물리적 설계는 하드웨어·운영체제 특성을 고려해 인덱스 구조·내부 저장 구조를 설계하는 단계이고, 구현은 SQL을 DBMS에서 실행해 DB를 생성하는 단계이다. (p.66)
- 별첨으로 트랜잭션과 ACID 특성(원자성·일관성·격리성·지속성) 및 대응 DBMS 기능(회복, 병행 제어)이 수록되어 있다. (p.76-85)

## 시험·과제 포인트
- 5개 변환 규칙을 "입력 ER 구조 → 결과 릴레이션"으로 적용: 특히 n:m의 복합 기본키(p.41), 1:n 외래키는 n측(p.43), 약한 개체의 복합 기본키(p.44), 1:1 세 경우(p.46-48), 다중 값 속성 분리(p.52).
- 한빛 마트 요구 사항에서 개체·속성·관계 추출 및 최종 릴레이션 5개(p.19, p.28, p.62).
- 회원 테이블 명세서와 CREATE TABLE 구현(p.63, p.71).
- 원문 표시 사항: p.44 좌석번호 부분키 표기 [판독 불확실]; p.56 게시글 글번호 밑줄 없음; p.41·43 예시는 한빛 마트와 속성이 다름; p.68~70 캡처 이미지(Recent Update 라벨); p.74 빈 슬라이드.
- 슈퍼/서브타입 변환 규칙은 8장 원문에 없음.
