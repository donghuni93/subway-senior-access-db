## 정의
트랜잭션의 4가지 특성: 원자성, 일관성, 격리성, 지속성 (p.78).
## 핵심 내용
- 원자성(Atomicity): 연산들이 모두 정상 실행되거나 하나도 실행되지 않는 All-or-nothing. 도중 장애 시 지금까지의 처리를 모두 취소하고 작업 전 상태로 되돌림 (p.78).
- 일관성(Consistency): 성공 수행 후에도 데이터베이스가 일관된 상태 유지 (p.81).
- 격리성(Isolation): 수행 중인 트랜잭션이 완료될 때까지 다른 트랜잭션이 중간 연산 결과에 접근할 수 없음. 동시 수행되어도 순서대로 하나씩 수행되는 것처럼 정확한 결과를 얻도록 제어 필요 (p.83).
- 지속성(Durability): 성공 완료 후 반영한 결과는 영구적 (p.85).
- 특성 보장에 필요한 DBMS 기능 (p.85): 원자성=회복, 일관성=병행 제어, 격리성=병행 제어, 지속성=회복.
## 예시
- 원자성 성공(p.79): 두 UPDATE 모두 실행 → 성호 5,000 / 은경 5,000. 실패(p.80): 1번과 2번 사이 장애 → 작업 취소, 성호 10,000 / 은경 0으로 복귀.
- 일관성 만족(p.81): 이체 전후 잔액 합계 10,000원. 불만족(p.82): 성호 5,000 / 은경 0, 합계 5,000원, "모순된 데이터가 존재".
- 격리성 만족(p.83): 계좌이체 후 은경 5,000 → 계좌입금 1,000원 → 은경 6,000원. 불만족(p.84): 이체 중간 상태(성호 5,000 / 은경 0)에 계좌입금이 접근, "모든 트랜잭션이 완료된 후 은경의 계좌 잔액은 얼마일까?"라는 질문만 제시(답은 원문에 없음).
## 흔한 실수/혼동
일관성과 격리성은 모두 병행 제어 기능에 대응하고, 원자성과 지속성은 회복 기능에 대응한다(p.85).
