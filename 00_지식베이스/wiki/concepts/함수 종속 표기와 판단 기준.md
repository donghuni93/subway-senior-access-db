## 정의
함수적 종속성(FD)은 속성들 간의 관련성이다 (p.10). "X가 Y를 함수적으로 결정한다"는 릴레이션 내의 모든 투플에서 하나의 X 값에 대한 Y 값이 항상 하나임을 뜻하며 X → Y로 표현한다 (p.11). 일반 정의는 [[함수 종속]](05장) 카드 참조.

## 핵심 내용
- X는 결정자, Y는 종속자. "Y가 X에 함수적으로 종속되어 있다"와 같은 의미. X, Y는 한 릴레이션 속성들의 부분 집합 (p.11).
- 판단 시 유의 (p.10): 속성 자체의 특성과 의미 기반으로 판단한다. 속성 값은 변할 수 있으므로 현재 릴레이션의 값만으로 판단하면 안 된다. 기본키와 후보키는 다른 모든 속성을 함수적으로 결정한다. 기본키나 후보키가 아니어도 다른 속성 값을 유일하게 결정하면 결정자가 될 수 있다.
- 고려하지 않는 당연한 FD (p.12): 고객아이디 → 고객아이디, {고객아이디, 이벤트번호} → 이벤트번호.
- 표기: 고객아이디 → 고객이름 / 고객아이디 → 등급, 또는 고객아이디 → (고객이름, 등급) (p.14). 함수 종속 다이어그램은 FD를 도식화한 것.

## 예시
고객 릴레이션(p.13): (고객아이디, 고객이름, 등급) = (apple, 정소화, gold), (banana, 김선우, vip), (carrot, 고명석, gold), (orange, 김용욱, silver). 각 고객아이디에 고객이름과 등급이 하나뿐이므로 고객아이디 → 고객이름, 고객아이디 → 등급.

이벤트참여(고객아이디, 이벤트번호, 당첨여부, 고객이름)의 FD (p.16):
- 고객아이디 → 고객이름
- {고객아이디, 이벤트번호} → 당첨여부
- {고객아이디, 이벤트번호} → 고객이름 (고객이름은 일부인 고객아이디에 종속 → 부분 함수 종속)

## 흔한 실수/혼동
현재 보이는 값만으로 FD를 단정하지 않는다. 결정자가 꼭 기본키일 필요는 없다.
