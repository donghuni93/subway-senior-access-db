## 정의
인터넷으로 회원에게 상품을 판매하는 한빛 마트의 데이터베이스 개발 예제. 8장 전체의 본 예제이다 (p.8).
## 핵심 내용
- 요구 사항 명세서(그림 8-4) 14문장 요지: 회원(회원아이디 식별), 상품(상품번호 식별), 제조업체(제조업체명 식별), 게시글(글번호 식별) 정보 유지 / 회원-상품 다대다 주문 / 상품-제조업체 공급 / 회원-게시글 작성 (p.8).
- 추출 결과: 개체 4개(회원, 상품, 제조업체, 게시글), 관계 3개(주문, 공급, 작성) (p.19, p.28, p.32).
- 최종 릴레이션 5개: 회원, 상품, 제조업체, 게시글, 주문 (p.62).
## 예시
| 개체 | 속성 (p.19) |
|---|---|
| 회원 | 회원아이디, 비밀번호, 이름, 나이, 직업, 등급, 적립금 |
| 상품 | 상품번호, 상품명, 재고량, 단가 |
| 제조업체 | 제조업체명, 전화번호, 위치, 담당자 |
| 게시글 | 글번호, 글제목, 글내용, 작성일자 |
## 흔한 실수/혼동
- 변환 규칙 설명용 그림(p.41, p.43 등)의 예시는 한빛 마트가 아니라 고객/주문/상품, 제조업체-공급-상품(공급수량) 등으로 속성이 다르다. 예) p.41 고객 속성 고객번호·이름·주소·등급, 주문 속성 주문수량 / p.43 공급 관계 속성 공급수량(본 예제는 공급일자·공급량).
- p.56 게시글 릴레이션은 글번호에 밑줄 표시가 없다(원문 표시 사항). p.58 이후에는 밑줄이 있다.
