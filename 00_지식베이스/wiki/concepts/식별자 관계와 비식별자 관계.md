## 정의
두 엔티티 타입 사이의 관계 유형은 업무, SQL, 자식테이블의 PK 구성 전략에 의해 결정된다 (p.57). 식별자 관계는 부모 PK가 자식 PK 영역에 포함되고(실선), 비식별자 관계는 부모 PK(FK)가 자식 일반 속성에 포함된다(점선).

## 핵심 내용 (p.63)
| 구분 | 식별자 관계 | 비식별자 관계 |
|---|---|---|
| 목적 | 강한 연결 관계 표현 | 약한 연결 관계 표현 |
| 자식 PK 영향 | 자식 PK의 구성에 포함됨 | 자식 일반 속성에 포함됨 |
| 표기법 | 실선 | 점선 |
| 연결 고려사항 | 반드시 부모 종속, 자식 PK에 부모 PK 포함, 상속받은 PK를 타 엔티티에 이전 | 약한 종속, 자식 PK 독립 구성, 부모 쪽 관계 참여가 선택 관계, 재상속 차단 필요 |

- 식별자 관계만 사용 시(p.58-60): PLANT → EQUIPMENT → EQPSTS → EQPEVTSTS → 이력 테이블로 계속 연결되어 주식별자의 속성 수가 많아지고, 세 테이블 조회 SQL(EQPEVTSTSHST A, EQP_ITEM B, EQP_WORKER C)은 PLANT, EQUIPMENT_ID, STATUS_SEQ, EVENT_ID, TRANS_TIME의 조인 조건이 반복되어 복잡해진다.
- 비식별자 관계만 사용 시(p.61-62): REP001T, REP005T, REP007T가 점선으로 연결되어 PK 속성이 차단되고, REP007T에서 점검번호='301' 조회에 3개 테이블 조인이 필요하다. 식별자 관계에서는 `SELECT A.기본가중치, A.조정가중치 FROM REP007T A WHERE A.점검번호='301'`로 충분하다.
- 비식별자 설정 고려(p.63): 관계의 강/약 분석(약한 관계), 자식테이블의 독립 PK 필요, SQL 복잡도 증가·개발생산성 저하를 줄이는 PK 속성 단순화.

## 예시
[판독 불확실] p.58의 오른쪽 아래 박스는 제목이 원문에 "EQUIPMENT"로 표기되어 있으나 내용상 EQPEVTSTSHST로 보인다. 확정하지 않는다. (p.59에는 EQPEVTSTSHST로 표기됨)
[판독 불확실] p.61 REP001T 등 일부 속성명(REP001T의 반복된 "프로젝트" 계열 속성 등)은 해상도 낮음/겹침으로 판독이 불확실하다. 속성 목록을 임의로 확정하지 않는다.

## 흔한 실수/혼동
식별자 관계는 PK가 길어지고, 비식별자 관계는 조회 시 조인이 늘 수 있다. 어느 쪽이 항상 낫다는 결론은 원문에 없다.
