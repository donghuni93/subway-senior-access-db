# 인수인계: 연구실 서버에서 API 수집 시작 (11/17 작성)

> 서버의 VS Code(Remote-SSH)에서 새 채팅을 시작할 때 이 파일을 Claude에게 준다.
> 프로젝트 전체 맥락은 저장소 루트 `README.md`, 단계별 할 일은 `04_본프로젝트/README.md`에 있다.

## 1. 상황

- 프로젝트: 엔지니어링DB 텀프로젝트. 고령 이용 수요와 승강기 운영 정보를 통합한 서울 지하철 이용 지원 시스템. 팀은 이동훈(조장), 박재연.
- 이 인수인계의 목적: 승강기 상태는 지난 시간의 값을 나중에 받을 수 없어서, 11/17~11/18 안에 수집을 시작하는 것이 최우선이다. 이미 개인 PC에서 매시 수집 중이지만 PC가 꺼지면 빠지므로, 연구실 서버에서도 수집해 결측을 줄인다.
- 수집 기간: 11/18~12/8 (제안서의 11/10~12/1에서 변경). 12/3 발표는 약 2주분으로, 12/10 최종 제출은 3주분으로 한다.

## 3. 서버에서 할 일 (순서대로)

1. ZIP을 푼다: `unzip seoul_subway_collector.zip && cd seoul_subway_collector`. Windows PowerShell로 만든 ZIP이라 경로 구분자 경고가 나올 수 있으나 파일은 정상이다.
2. 인증키: `.env.example`을 `.env`로 복사하고 `SEOUL_API_KEY=키`를 넣은 뒤 `chmod 600 .env`. 키는 ZIP에 없으며, 사용자가 별도로 준다.
3. 환경 확인: `python3 --version`(3.9 이상), `date`(시간대 KST인지).
4. 수동 실행: `python3 src/collect.py`. `ok 2809`, `ok 871`, `ok 8` 세 줄이면 성공.
   - error가 나면 서버 방화벽 가능성이 크다. 서버에서 `openapi.seoul.go.kr` 8088 포트로 나가는 접속이 열려 있어야 한다. 막혀 있으면 사용자가 서버 관리자에게 요청한다. ZIP 안 `README.md` 5장에 오류별 조치가 있다.
5. 자동 실행 등록: `crontab -l`이 동작하면 `0 * * * * /절대경로/run_collect.sh`를 `crontab -e`로 추가한다. cron을 못 쓰면 nohup 반복 방식을 쓴다(재부팅 시 멈춘다).
6. 등록 직후 정시를 한 번 지나 스냅샷이 쌓이는지 확인한다.
7. 다음 날 아침: `python3 check_snapshots.py`로 소스별 24개 근처, 실패 0건인지 본다. 이것이 프로젝트 README의 0-6 항목이다.

## 4. 지켜야 할 것

- **인증키를 대화, 로그, Git, 문서에 남기지 않는다.** 수집기는 오류 메시지에서 키를 가리지만, 사용자가 키를 채팅에 붙여넣지 않게 안내한다.
- `data/snapshots/`의 원본 파일은 수정하지 않는다. 가공은 나중에 이 파일을 읽어서 한다.
- 서버의 `collect.py`를 고치면 개인 PC의 같은 파일과 갈라진다. 고치면 사용자에게 알려 두 곳을 맞춘다.
- 서버는 연구실 공용이다. 매시 3회 호출은 가볍지만, 연구실 관리자에게 3주 동안 작업이 돈다는 것을 알려야 한다. 사용자가 할 일이다.

## 5. 결정이 남아 있는 것 (사용자 몫)

| 결정 | 선택지 | 추천 |
|---|---|---|
| 서버 자동 실행 방식 | cron / nohup 반복 | cron을 쓸 수 있으면 cron |
| 두 곳 수집 여부 | 서버 단독 / 서버+개인 PC 병행 | 서버가 안정될 때까지 병행. 같은 시각 스냅샷이 둘 있으면 적재 때 한쪽만 쓴다 |
| 결측 시각 처리 | 직전 상태 유지 / 알 수 없음 | 알 수 없음으로 표시하고 따로 집계 (2단계 `build_outage.py`에서 정한다) |
| 서버 재부팅 확인 | 서버 관리자에게 점검·재부팅 일정 문의 | 일정 파악 후 해당 시각은 결측으로 기록 |

## 6. 이후 이어질 일

수집이 돌기 시작하면 1단계(파일 데이터 확보와 설계 확정, 11/18~11/21)로 넘어간다. 설계 문서는 `design/`에 있고 초안은 `02_ER다이어그램.md`, `03_릴레이션스키마.md`이다. 서버에서 모은 `data/snapshots/` 폴더는 수집 종료 때, 또는 중간 분석이 필요할 때 통째로 압축해 팀 PC로 가져온다(1회 약 58KB, 3주 약 30MB).
