## 4. 지켜야 할 것

- **인증키**: 저장소 루트 `.env`의 `SEOUL_API_KEY`에만 둔다. 채팅·로그·문서·zip에 넣지 않는다. 증빙 zip을 만들 때 `.env`가 빠졌는지 확인한다.
- **DB 비밀번호**: 코드와 `.env`에 두지 않는다. 모든 프로그램이 MySQL login-path `endb`로 접속한다.
- **다른 DB**: `subway_db`는 HW2용이므로 건드리지 않는다.
- **원본 보존**: `data/snapshots/`와 `data/raw/`의 파일은 고치지 않는다. 가공은 언제나 이 파일을 다시 읽어서 한다.
- **스키마 재생성 주의**: `sql/01_schema.sql`을 실행하면 DB를 지우고 새로 만든다. 스키마를 바꿀 때만 실행하고, 그 뒤에는 `load_db.py`(전체)와 `sql/04_views.sql`을 다시 실행한다. PowerShell에서는 상대경로 때문에 다른 파일이 실행된 적이 있으니 저장소 루트에서 실행하거나 절대경로를 쓴다.
- **다른 세션 담당 파일**: `src/collect.py`, `tests/test_collect.py`, `output/seoul_subway_collector.zip`, `인수인계_서버수집.md`, `파이프라인_현황.md`는 서버 수집 담당 세션이 관리한다. 고쳐야 하면 먼저 알린다.
- **PC 전원**: 수집은 이 PC가 켜져 있을 때만 된다. 절전이나 종료 시간은 영구 결측이 된다.

## 5. 알아 두면 좋은 설계 규칙

- **역 식별**: `station_no`는 승하차 파일의 역번호이자 API의 역코드(STN_CD) 정수다. 외부코드는 `fr_code`로 따로 둔다. 역명으로 맞출 때는 `preprocess.py`의 `RENAMED`(역명 변경·줄임 표기 별칭)를 쓴다. 정제 후 `data/clean/unmatched.csv`에 새 행이 생기면 별칭을 추가한다. 8호선 암사와 암사역사공원은 서로 다른 역이므로 묶지 않는다.
- **환승역**: 승하차·승강기가 한 호선 코드로만 기록되므로 분석과 화면은 역사(`station_complex`, 278개 역 → 242개 역사) 단위로 한다. `complex_id`는 묶음 안의 가장 작은 역번호다.
- **비가동 구간**: 직전 스냅샷과 비교해 '사용가능'이 아닌 상태가 처음 보인 시각을 시작, 다시 '사용가능'으로 보인 시각을 종료로 한다. 스냅샷이 아예 없는 시각은 건너뛰므로 PC가 꺼졌던 시간만큼 비가동 시간이 길게 잡힐 수 있다. 처음 관측했을 때 이미 보수 중이었거나 수집 공백(70분 초과) 직후에 처음 보인 비가동은 실제 시작 시각을 모르므로 `outage.start_known = 0`으로 표시하고 비가동 횟수·시간 통계와 우선 관리 점수에서 뺀다(11/17 14시 기준 99건 중 94건). 지금 멈춘 승강기 현황에는 모두 포함한다.
- **군집 회차**: `analysis.py`를 실행할 때마다 `cluster_run`에 새 회차가 쌓이고 화면은 최신 회차(`v_cluster_latest`)를 보여 준다. 수집이 72시간(`MIN_COLLECT_HOURS`) 미만이면 비가동 지표를 빼고 실행한다.
- **시간대 프로필**: 화면 속도를 위해 `ridership_profile`에 역사·평일/주말·시간대별 평균을 미리 계산한다. `load_db.py` 전체 실행 때 다시 계산된다. 2025년 공휴일 17일은 주말로 친다.
- **서버 스냅샷을 합칠 때**: 서버에서 모은 파일을 `data/snapshots/{source}/`에 넣고 `preprocess.py` 전체를 다시 실행하면 된다. 같은 파일명(같은 분)이 겹치면 한쪽만 둔다.
- `run_collect.cmd`는 가상환경 파이썬 경로(`C:\Users\dongh\.venvs\endb`)를 직접 적어 두었다. 다른 PC로 옮기면 이 경로를 바꾼다.
